# Security Assessment Scope

## 1. Engagement Overview

Sulaiman Solutions Sdn. Bhd. is a fictional organization created for this simulated cybersecurity engagement.

The purpose of the assessment is to evaluate the security posture of a controlled enterprise-style lab environment by identifying vulnerabilities, validating selected security weaknesses, analyzing potential attack paths and documenting their security impact.

All testing is performed within systems specifically configured for this project.

---

## 2. Assessment Objectives

The engagement aims to:

- Identify active systems and exposed network services.
- Enumerate discovered services and applications.
- Identify potential network and web application vulnerabilities.
- Validate selected findings where safe and appropriate.
- Analyze potential attack paths.
- Assess the likelihood and impact of identified vulnerabilities.
- Recommend practical remediation measures.
- Produce professional technical and executive-level security documentation.

---

## 3. In-Scope Systems

The exact IP addresses and system information will be documented after the lab environment has been configured.

| Asset | Function | Scope |
|---|---|---|
| Vulnerable Linux Server | Simulated enterprise server | In Scope |
| Vulnerable Web Application | Simulated company web application | In Scope |
| Internal Lab Network | Controlled assessment network | In Scope |

The security assessment workstation used to conduct testing is not considered an assessment target.

---

## 4. Permitted Activities

The following activities are authorized within the controlled lab environment:

- Host discovery
- Network scanning
- Port scanning
- Service enumeration
- Web application assessment
- Vulnerability identification
- Vulnerability scanning
- Manual vulnerability verification
- Controlled exploitation of selected vulnerabilities
- Network traffic analysis
- Attack-path analysis

---

## 5. Out-of-Scope Activities

The following activities are excluded from the assessment:

- Denial-of-service attacks
- Destructive testing
- Testing of external or third-party systems
- Social engineering against real individuals
- Testing of production infrastructure
- Persistence outside the controlled lab
- Destructive modification or deletion of system data
- Any activity affecting systems outside the defined environment

---

## 6. Rules of Engagement

Testing will only be performed against systems specifically configured as part of the controlled lab environment.

Any exploitation performed during the assessment will be limited to the minimum activity required to validate a vulnerability and demonstrate its potential impact.

Testing will stop if any activity creates an unexpected risk to systems outside the defined environment.

No real organizations, customers or production systems are involved in this assessment.

---

## 7. Evidence Handling

Technical evidence may include:

- Screenshots
- Command output
- Scan results
- HTTP requests and responses
- Network observations
- Vulnerability validation evidence

Only evidence relevant to the assessment findings will be retained within the portfolio.

Sensitive information, credentials, tokens or unnecessary raw data will not be published.

---

## 8. Deliverables

The assessment will produce:

- Environment documentation
- Security assessment methodology
- Technical vulnerability findings
- Supporting evidence
- Attack-path analysis
- Risk classification
- Remediation recommendations
- Executive summary
- Final cybersecurity assessment report
